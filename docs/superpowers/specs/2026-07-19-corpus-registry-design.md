# Corpus registry: consolidate data/ corpora + selectable/union loader

**Date:** 2026-07-19
**Status:** Approved

## Problem

`data/` holds three interchangeable serving corpora that share the schema
`{id, title, contents, metadata}` but are otherwise disconnected:

| File | Docs | Domain | Origin |
|------|------|--------|--------|
| `corpus.jsonl` | 30 | retrieval/ML (curated) | hand-written demo corpus |
| `corpus_scifact.jsonl` | 5,183 | scientific | generated by `beir_to_corpus.py` |
| `corpus_nfcorpus.jsonl` | 3,633 | medical | generated by `beir_to_corpus.py` |

The demo/hybrid retrieval servers can only load **one** corpus, chosen by a raw
`--corpus_path` filesystem path. There is no single place that names "which
corpora exist," and no way to search across them — so the demo's coverage (and
vocabulary) is capped at 30 ML docs even though ~8,800 more docs sit unused.

Alongside this, `data/` has accumulated zero-reference dead weight:
`case.txt` (0 bytes), `intent_examples.sample.json` (byte-identical duplicate of
`intent_examples.json`), a stray root `data/vocabulary_corpus.json` (the
generated copy lives at `data/indexes/vocabulary_corpus.json`), and an empty
`data/nq_rag/` directory.

## Goal

A **corpus registry** as the single source of truth for available corpora, plus
a loader that can serve a **named corpus or a union of corpora** — extending
what the demo/hybrid search can answer — without changing the curated demo's
default behavior or touching BEIR eval.

## Design

### 1. Manifest — `data/corpora.json`

Single source of truth naming each corpus:

```json
{
  "demo":     {"path": "data/corpus.jsonl",          "domain": "retrieval/ML", "docs": 30},
  "scifact":  {"path": "data/corpus_scifact.jsonl",  "domain": "scientific",   "docs": 5183},
  "nfcorpus": {"path": "data/corpus_nfcorpus.jsonl", "domain": "medical",      "docs": 3633}
}
```

`domain`/`docs` are descriptive metadata (used in the load-summary log); only
`path` is load-bearing.

### 2. Resolver — `src/internal/servers/retrieval/corpus_registry.py` (new)

- `load_manifest(path: str = "data/corpora.json") -> dict[str, dict]` — parses
  the manifest. Missing file → empty manifest (path-only mode still works).
- `resolve_corpus_docs(spec: str, manifest: dict | None = None) -> list[dict]`:
  - `spec` is a registry name (`"demo"`) → load that corpus's file.
  - `spec == "all"` → union of every registered corpus, **deduped by `id`**
    (first occurrence wins; a WARNING is logged per dropped duplicate id).
  - `spec` is a comma-separated list of names (`"demo,scifact"`) → union of those.
  - `spec` is an existing filesystem path → load it directly (back-compat with
    today's `--corpus_path`).
  - Unknown name that is neither a manifest key nor an existing path →
    `ValueError` listing the available names.
  - Loads each file via the existing `demo._load_corpus`; emits one INFO line
    summarizing what was loaded (names + total doc count) so nothing is silently
    truncated.

### 3. Loader wiring — `demo.py` + `hybrid.py`

- Add `TfidfRetriever.from_docs(docs: list[dict]) -> TfidfRetriever` classmethod.
  Refactor `__init__(corpus_path)` to `_load_corpus` then delegate to a shared
  `_build(docs)` builder; `from_docs` calls `_build` directly. The existing
  `__init__(corpus_path)` signature and all 5 current call sites stay unchanged.
- Add a `--corpus` CLI flag (registry name / `all` / comma-list) to both servers,
  next to the existing `--corpus_path`. Exactly one is required; `--corpus_path`
  remains fully supported (default demo run is unchanged). `main()` resolves the
  chosen spec to `docs` via `resolve_corpus_docs`, then builds the sparse
  retriever with `TfidfRetriever.from_docs(docs)`. `hybrid._build_dense` consumes
  the same resolved `docs` rather than re-reading a path.

### 4. Cleanup (folded in)

Delete (all verified zero-reference):
- `data/case.txt` — 0 bytes, no references.
- `data/intent_examples.sample.json` — byte-identical to `intent_examples.json`;
  no code references. Keep `intent_examples.json`.
- `data/vocabulary_corpus.json` (root) — no code readers; the generated artifact
  is written to `data/indexes/vocabulary_corpus.json` by
  `document_index/cli.py`. Keep the `data/indexes/` copy.
- `data/nq_rag/` — empty directory; scripts recreate it as a `--local_dir`
  target on demand.

## Scope / non-goals

- **Not** merging or regenerating the `vocabulary_corpus.json` artifact. It
  belongs to the heavier BM25 `document_index` pipeline, not the demo TF-IDF
  server (which fits its own vectorizer at runtime). The searchable vocabulary
  broadens automatically once the server loads the union.
- **Not** touching BEIR eval. `beir_eval.py` loads `data/beir/<dataset>/` in raw
  BEIR format via `GenericDataLoader`; the `corpus_*.jsonl` files it never reads.
- **Not** gitignoring / removing the large BEIR `.jsonl` corpora (regenerable via
  `beir_to_corpus.py`) — noted as a possible follow-up, out of scope here.
- **Not** changing the frontend example chips (separate open PR #428).

## Verification

- `resolve_corpus_docs` unit tests: name → correct file; `all` → union with
  duplicate-id dedupe; comma-list → union of the named subset; existing path →
  loads directly; unknown spec → `ValueError` naming available corpora; missing
  manifest → path-only mode still works.
- `TfidfRetriever.from_docs(docs)` builds a working retriever (retrieve returns
  ranked hits); the 5 existing `TfidfRetriever(path)` call sites are untouched
  and still pass.
- `demo.py` / `hybrid.py` start with `--corpus_path data/corpus.jsonl` (default,
  unchanged) and with `--corpus demo` (equivalent) and `--corpus all` (loads
  8,846 docs); `--corpus bogus` exits with a clear error.
- Cleanup: the four deleted paths are gone; full unit suite green; `ruff` clean.
