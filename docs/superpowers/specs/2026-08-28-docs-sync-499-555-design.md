# Docs sync for #499–#555 — design

## Problem

`README.md` and `docs/*.md` are a running mirror of merged `main`. Fifty-seven PRs
merged since the last sync baseline (#498). Most shipped their own doc changes as
they landed; the question is which *behavioural* claims are now false.

## Scope

A sync is **not** a reorganisation or a style pass. It corrects claims that merged
code invalidated, and nothing else. Pure-internal refactors are skipped — except
where a doc *names a module path*, which this repository's docs do constantly, so
the #535–#544 and #553–#555 module moves are in scope as observable facts.

PR #556 (unseen-user evaluation) is deliberately **excluded**: it is open, and docs
describe merged `main`. That is tracked debt — a follow-up sync is required the
moment it lands.

## Method

Verify against code, never against PR bodies. A term can outlive the code by months.

Three checks, scripted so they can be re-run:

1. **Link + anchor resolution** over `README.md` + `docs/**/*.md`.
2. **`docs/architecture.md` repository tree vs. the repo**, compared against
   **`git ls-files`, not the filesystem** — an untracked `__pycache__` or build
   artifact makes a dead directory look alive.
3. **Path existence** for every `src/`, `examples/`, `bin/` path a doc names.

Then targeted behavioural checks on the user-visible arcs: streaming (#546/#548),
session ownership (#499/#500/#532/#534), tools (#502/#503/#505), post-training
shape (#528/#539), store concurrency (#545).

## Known non-findings

`data/*` paths resolve as "missing" because `data/` is gitignored — those are
outputs, not repo files. Several `tests/.../path_to/...` mentions are doc
placeholders. Both are expected and were confirmed, not silenced.
